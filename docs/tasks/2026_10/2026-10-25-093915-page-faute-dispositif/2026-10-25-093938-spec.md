# La page nomme une faute de dispositif

## 1. Le défaut, mesuré

Le run `2026-10-24-213727-0b91f5df-defect-racine-terrain` porte `verdict: non concluant`,
`causes: [dispositif, cas]`, aucun geste mesuré hors cadre, et une promesse signée `mord` par le juge. Sa
page, écrite par `resultat.mjs` sur une copie, disait :

> **Non concluant, cause dispositif et cas.** Le run n'a pas pu être mesuré jusqu'au bout. Ni le skill ni la
> session ne sont jugés ; le run est à rejouer.

Or son §3 portait déjà `| la promesse du skill, branche P | … | violé |`, et son §4 nommait « le dispositif
et le cas » avant de conclure « c'est le run qui manque ». La page se contredisait, et sa §1 renvoyait la
faute à un « run » sans couche. Cause : `sectionVerdict` ne recopiait la signature que pour une faute de
session (`FAITS_SESSION`) ; une cause `dispositif` tombait au repli, qui ne lit ni la cause ni la
signature.

Le cas `2026-10-24-213712-defect-racine-terrain` ne déclarait aucune `lecture.json` : aucune page ne
pouvait exister, même après correction.

## 2. Ce qui change

- **`sectionVerdict`** : une branche nouvelle, avant le repli, quand le reçu porte la cause `dispositif` et
  qu'aucun geste de session n'est mesuré. Elle dit que le dispositif n'a pas mesuré le run jusqu'au bout,
  recopie la signature (motif et conséquence si elle mord, promesse tenue sinon, absence de juge sinon), et
  nomme la suite : le skill est en cause et le run reste à rejouer, ou le skill n'est pas condamné.
- **`sectionFautes`** : le §4 dit « c'est le dispositif qui n'a pas conclu, pas la session » au lieu de
  « c'est le run qui manque ».
- **`sectionGestes`** : quand la promesse est signée et que la cause est `dispositif`, le geste de protocole
  demande de rejouer le cas pour que ce défaut devienne une mesure, et non reste une lecture.
- **La lecture du cas `2026-10-24-213712-defect-racine-terrain`** : cinq rangs déclarés depuis la trace et
  le reçu du run — lecture du skill, lecture du README, des tests et de l'observation, tableau et pause,
  produit au chemin nommé, rien hors produit — plus un geste de cadre sans rang. Chaque assertion est une
  mesure que le reçu porte réellement : aucune n'est ajoutée pour faire tenir une clause.
- La page du run `2026-10-24-213727` est écrite par `rapport` ; le `RAPPORT.md` du même run reste
  identique octet pour octet.
- **`dossierProduit`** : le premier segment du chemin produit n'est un dossier que s'il en existe un. Un
  produit unique à la racine d'écriture fait dire « sous `aidd_docs/` », jamais
  « sous `aidd_docs/<fichier>.md/` ». Le défaut était visible sur la première page produite, qui prenait le
  fichier pour un dossier.

## 3. Ce qui ne change pas

- Le reçu, l'output et la signature : la correction est dans la page, pas dans la preuve.
- La page de `plan-simple` : même `sha256` après la correction (`7b0fc4c5…`), parce que sa cause est
  `modele` et qu'aucune branche nouvelle ne la touche.
- Le plafond de soixante lignes, les six sections, les mots interdits et le déterminisme.

## 4. Le contrôle de banc

**331**, sur une copie du run réel `2026-10-24-213727` — reçu, produit et signature copiés, pages dérivées
retirées — avec la `lecture.json` et l'attendu du cas `2026-10-24-213712-defect-racine-terrain`. La page
doit : nommer la cause au §1, dire que le dispositif n'a pas mesuré le run, ne pas dire que personne n'est
jugé, garder sa dernière clause `violé`, rendre la faute au dispositif au §4, et proposer au §6 de rendre
le défaut mesurable.

Son mutant neutralise la branche (`} else if (dispositif) {` → `} else if (false) {`) : la page retombe sur
« ni le skill ni la session ne sont jugés » et le contrôle meurt sur « §1 ne nomme pas le dispositif ».

**332**, sur la même page : le dossier du produit est `aidd_docs/`, et le nom du fichier n'est jamais
suivi d'une barre oblique. Le mutant qui reprend le premier segment sans distinguer fichier et dossier
meurt sur « §5 prend le fichier pour un dossier ».

## 5. Critère de sortie

Le banc passe de **330** à **334** contrôles, le 331 et le 332 compris avec leurs mutants ; la page du run
`2026-10-24-213727` existe, fait moins de soixante lignes, nomme le dossier du produit et ne se contredit
pas ; celle de `plan-simple` est inchangée ; `runs.mjs --verifier` et `liens.mjs` rendent `0`.

## 6. Ce que ce contrôle ne prouve pas

Il prouve que la page lit la cause et la signature, pas que la cause est bien attribuée : `dispositif` est
une déclaration du reçu, que la page recopie. Il ne prouve pas non plus que le défaut du dispositif est
mesurable ; les règles 324 à 326 le ferment pour l'erreur terminale, le produit incomplet et le cadre non
livré, pas pour ce run-là, qui précède leur écriture.
