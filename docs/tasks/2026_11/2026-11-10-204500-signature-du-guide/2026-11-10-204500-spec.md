# Spec — une signature des clauses pour le run guidé

> V0.1, 2026-11-10, née à 20:45. Source : [ADR-116](../../../DECISIONS.md), et le run guidé du
> 2026-11-10-200210 dont la comparaison était déclarée par son producteur.

## 1. Le défaut

Un run guidé porte `intention` et `comparaison`, mais la comparaison est écrite par celui qui a produit :
« tenu » y est une auto-évaluation. Le mode indépendant a `promesse-signee.json` et un juge nommé ; le
guidé n'a rien. Son meilleur statut reste `forme tenue`, qui ne dit que la forme des pièces.

## 2. La règle

Un run guidé peut porter `signature.json` dans son dossier, à côté de `run.json`. La pièce est écrite par
un **second relecteur**, nommé, qui lit le produit et la grille et signe chaque clause de la comparaison :

```json
{
  "type": "signature-guide",
  "juge": "qui signe",
  "quand": "2026-11-10T20:45:00+01:00",
  "rubrique": "ce qu'il a lu",
  "motif": "ce qu'il ne pouvait pas vérifier",
  "clauses": [
    { "clause": "le texte exact d'une clause de comparaison", "etat": "tenu", "preuve": "la pièce citée" }
  ]
}
```

`signature.json` est une pièce du run : `pieces` le cite. `runs.mjs` exige que l'ensemble des clauses
signées soit **égal** à celui de `comparaison` : aucune clause facile signée seule, aucune clause inventée.
Le statut `forme tenue signée` n'est accepté qu'avec une signature complète dont toutes les clauses sont
`tenu` ; une clause signée `violé` interdit ce statut et laisse `forme non tenue`. Une signature présente
qui ne couvre pas la comparaison est refusée.

## 3. Ce que la signature est, et n'est pas

C'est une **déclaration d'un relecteur nommé**, pas une mesure : `runs.mjs` vérifie la forme, la couverture
et la cohérence avec la comparaison ; il ne vérifie ni l'identité du relecteur, ni la fidélité de sa
lecture, ni qu'il est indépendant du producteur. Ce que le relecteur ne pouvait pas voir, il l'écrit dans
`motif`. Une signature ne remplace ni un reçu, ni un juge de promesse, ni un run indépendant.

## 4. Critère de sortie

- Quatre contrôles de banc : une signature complète acceptée, un statut signé sans pièce refusé, une
  signature partielle refusée, une clause violée sous statut signé refusée.
- `runs.mjs --verifier` reste à 0 sur le dépôt, et l'index montre la signature.
- Aucun cas gelé, aucun reçu, aucune autre commande du harnais n'est touché.

## 5. Ce qui rendrait cette spec fausse

Un statut `forme tenue signée` accepté sans signature. Une signature qui ne couvre qu'une partie des
clauses. Une signature qui contredit la comparaison sans refus. Une signature présentée comme une mesure
ou comme une indépendance. Une signature qui réécrit `run.json` ou le produit.
