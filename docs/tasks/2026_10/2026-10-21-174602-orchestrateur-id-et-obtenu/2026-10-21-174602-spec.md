# Spec : l'identifiant par défaut de `cas` et le `obtenu` de `porte`

> 2026-10-21, nom `2026-10-21-174602`. Les deux défauts sont mesurés par la Séance 96, en fabriquant
> le cas `2026-10-21-173843-plan-simple` : la route du protocole s'arrête au premier, le second fait
> dire à un bloc ce qu'il ne montre pas.

## 1. Les deux défauts

### 1.1 `cas` refuse sans `--id` quand le skill est un fichier

`orchestrer.mjs` dérive l'identifiant par défaut de `basename(skill)`, l'extension retirée :

```js
const id = option(valeurs, "id", { defaut: `${horodatage()}-${basename(skill).replace(/\.[^.]+$/, "")}` });
```

Pour un skill nommé `SKILL.md`, cela donne `SKILL`, et la majuscule sort du domaine
`/^[a-z0-9][a-z0-9-]*$/` : la commande refuse en `exit 2`. Mesuré le 2026-10-21 :

```text
USAGE — --id « 2026-10-21-173843-SKILL » hors domaine : des minuscules, des chiffres et des tirets
```

`--id` est pourtant présenté comme optionnel dans l'usage, et le banc ne l'a jamais vu parce que ses
contrôles `cas` passent tous `--id`. La même panne attend tout fichier dont le nom porte une majuscule,
`PLAYBOOK.md` compris.

### 1.2 `porte` tronque le JSON de la porte dans `obtenu`

```js
obtenu: readFileSync(join(run, "gate.json"), "utf8").replace(/\s+/g, " ").slice(0, 220),
```

Le bloc `▸ ÉTAPE` promet de recopier la sortie de la commande, pas de la résumer. Ici il coupe le JSON
au caractère 220, au milieu d'un chemin, sans ellipse : le lecteur ne peut pas savoir que la pièce est
tronquée. Le mode de `preflight` imprime pourtant une ligne complète, que `harnaisOuRefus` capture déjà
et que `porte` jette.

## 2. Objectif

1. `cas --skill <…>/SKILL.md` sans `--id` crée un cas nommé `<horodatage>-<dossier-du-skill>`, et
   `cas --skill <…>/PLAYBOOK.md` crée `<horodatage>-playbook` ; un `--id` fourni reste inchangé.
2. Le `obtenu` de `porte` est la ligne de `preflight`, entière : elle commence par `preflight ok`, elle
   nomme le `gate.json` écrit, et sa longueur n'est plus bornée à 220.

## 3. Conception

### 3.1 Le nom du skill, puis un slug

Une fonction dédiée, utilisée seulement pour le défaut :

```js
function slugDeSkill(skill) {
  const base = basename(skill);
  const nom = base.toLowerCase() === "skill.md" ? basename(dirname(skill)) : base.replace(/\.[^.]+$/, "");
  return nom.toLowerCase().replace(/[^a-z0-9]+/g, "-").replace(/^-+|-+$/g, "");
}
```

`SKILL.md` prend le nom de son dossier, parce que « skill » ne distingue aucun cas ; tout autre fichier
garde son nom sans extension. Un chemin qui ne donne aucun slug (`__`) est refusé par un message qui
nomme le remède, `--id`, au lieu de laisser le refus de domaine parler d'un identifiant vide.

### 3.2 Le vrai `obtenu`

`harnaisOuRefus` rend la sortie de `preflight` ; elle est gardée dans une variable et passée à
`uneLigne`, sans `slice`. Aucune autre ligne du bloc ne change, et le plafond de six lignes de l'ADR-040
n'est pas touché : c'est une longueur de ligne qui change, pas un nombre de lignes.

## 4. Les contrôles de banc

| N° | Ce qu'il fait | Ce qu'il exige |
| --- | --- | --- |
| 210 | `cas --skill $OSKILL --terrain $OTERRAIN --racine $O --cases $O/cases-id`, **sans** `--id` | une seule pièce `*.request.md`, un identifiant `<horodatage>-playbook`, les trois pièces présentes |
| 211 | `porte --cas cas-test --run $O/run-obtenu`, sortie capturée | la ligne `obtenu` commence par `preflight ok`, contient `gate.json`, et mesure plus de 220 caractères |

Le 211 est le garde-fou de la troncature : sous l'ancien code, la ligne coupée ne portait plus le
`gate.json` et faisait moins de 220 caractères. Le 210 est celui du défaut : sous l'ancien code, `cas`
sortait en `2` et n'écrivait rien.

## 5. Ce que ces contrôles ne prouvent pas

- **Un texte, une branche.** Le 211 lit la sortie imprimée ; il ne prouve pas que le JSON de la porte est
  intact sur le disque, seulement que le bloc montre la ligne que `preflight` a écrite.
- **La qualité du slug.** Le 210 prouve `playbook` pour un fichier et le dossier pour un `SKILL.md` ;
  il ne prouve pas qu'un nom exotique donne un identifiant lisible, seulement qu'il ne casse plus la
  commande ou qu'il est refusé avec son remède.
- **La session.** Aucun contrôle n'ouvre de fil : ils éprouvent l'orchestrateur, pas le dispositif en
  marche.

## 8. Risques et limites

- **Un identifiant par défaut reste un identifiant.** Il peut entrer en collision avec un cas existant ;
  `cas` refuse déjà un cas présent, et le refus nomme le fichier : le comportement ne change pas.
- **Le `obtenu` peut être long.** La ligne de `preflight` porte le dossier, le HEAD, le `porcelain`, le
  gel et la porte ; c'est ce que le bloc doit montrer, et l'ADR-040 ne borne que les lignes, pas les
  caractères.
- **Le banc ne voit pas le cas réel.** Les deux contrôles passent par le cas fabriqué du banc et le
  terrain du jouet ; aucun ne touche `CASES/`.
