# Bilan des pertes

Ce document dit où est passée chaque règle du contrat, et ce qui a été perdu au passage.
Il ne juge pas : il compte. La référence est l'état avant coupe, le noyau et les skills sont
l'état après.

Deux outils produisent ce rapport, et ils ne font pas le même travail :

| outil | rôle | sortie |
|---|---|---|
| `tools/guard-agents.mjs` | **refuse** une dérive | code 1, liste des refus |
| `tools/bilan-pertes.mjs` | **dit** ce qui manque | rapport, quatre catégories |

Le gardealone ne dit pas *pourquoi*. Le bilan ne peut pas empêcher. Ils se complètent.

## Le seul déplacement

```
TERRITORY → noyau:OUTPUT

* No production before a written spec: brainstorm → design doc → approved → only then code.
```

Une porte générale, pas une règle de dépôt. Dans un skill elle ne s'applique que si l'agent
active le skill, donc elle ne s'applique pas au moment où elle compte. Le texte est
identique ; seule sa maison a changé. Le bilan l'affiche au lieu de le masquer.

## Ce que le premier garde ne voyait pas

`tools/guard-agents.mjs` ne cherchait que dans les skills. La moitié des règles vit dans le
noyau, et une perte dans le noyau est plus grave qu'une perte dans un skill : elle est
chargée à chaque tour. Le garde teste maintenant les deux :

```
N1  skill manquant        REFUS  8 dérivations, dont « section orpheline : TERRITORY »
N2  règle amputée (skill) REFUS  « règle perdue : Only committed documents outlive memory… »
N3  section dupliquée     REFUS  « section à deux maisons : MEMORY — AGENTS.md ET 02-memory »
N4  règle amputée (noyau) REFUS  « règle perdue : Never commit or push… »
final                    ok
```

## Un désaccord que les deux outils ont tranché

Le premier bilan a rapporté une perte que le garde ne voyait pas : la ligne *« No production
before a written spec »* déplacée de `TERRITORY`. **Le garde avait raison** — la règle existe,
elle a changé de maison. Un déplacement n'est pas une perte. Le classement du bilan a été
corrigé, pas le garde.

Le fait que les deux outils aient disagreed sur la même règle est le meilleur test qu'ils
aient reçu : ils n'ont pas le même angle mort.

## Rejouer

```sh
node tools/guard-agents.mjs                    # refus, code 1 si dérive
node tools/bilan-pertes.mjs                    # compte, code 1 si perte
node tools/bilan-pertes.mjs --core <fichier>   # vérifie un noyau candidat
node tools/bilan-pertes.mjs --md <sortie>      # écrit le rapport en markdown
```

## Limite

Ce bilan compare du **texte**. Il dit qu'une règle est présente et identique. Il ne dit pas
qu'un agent l'exécute, ni qu'un skill se déclenche. Cette seconde mesure n'a pas été faite et
ne peut pas l'être sans une session réelle : `GET /api/skill` renvoie 34 skills sans
`location` et 0 avec, y compris pour un dépôt dont on sait que 34 skills chargent — la requête
est fausse, pas la convention.
