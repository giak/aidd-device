# Spec — l'installation déclarée

## 1. Le fait qui la demande

La [VISION](../../../VISION.md) fait de l'installation le deuxième temps de la boucle : un AIDD installé
dans un projet local. Le protocole ne le mesure pas. Le terrain est bien un projet (`416ec1f` pour
`plan-simple`, dont `origin` est `/home/giak/projects/audio-sync-tool`), et cinq des seize gels le nomment ;
mais rien dans le gel, dans la porte ni dans le reçu ne dit qu'AIDD y est installé, ni à quelle révision. Le
projet lui-même porte `AGENT.md` (21 441 octets, commit `416ec1f`) mais ni `aidd_docs` ni `.aidd` ; la
branche `origin/test/aidd-installation` pointe le même commit, sans différence : aucune trace d'installation
d'AIDD n'y est mesurable, et la déclaration du 2026-11-10 le constate. aucun moyen de savoir lequel la session a trouvé.

La porte vérifie l'état du terrain, `HEAD` complet et `porcelain` (`run.mjs:966`), ce qui ne dit rien des
fichiers qu'une installation laisse et que git ignore. Une installation non suivie est donc invisible : elle
peut manquer, ou vieillir, sans qu'aucun refus ne le dise.

## 2. Le champ au gel

Le cas déclare son installation dans un fichier de cas, `CASES/<cas>.installation.json`, de la même famille
que `.etalon.json` :

```json
{
  "geste": { "par": "giak", "le": "2026-11-10T06:00:00+01:00", "preuve": "…" },
  "fichiers": ["AGENT.md", "aidd_docs/PLAN.md"]
}
```

- `fichiers` nomme des fichiers **du terrain**, relatifs à sa racine ; un chemin absolu ou qui sort de
  l'arbre est refusé, comme les références du gel (`run.mjs:606`).
- `geste` est la déclaration humaine, citée comme telle : qui a installé, quand, sur quelle preuve. Elle
  n'est pas vérifiée, et c'est dit.

`freeze` mesure la déclaration comme il mesure les fichiers du cas : elle entre dans `fichiers` avec le rôle
`installation`, donc son `sha256` couvre l'empreinte du gel, la ligne d'empreinte portant le rôle
(`run.mjs:551`). Le gel reçoit alors

```json
"installation": {
  "arbre": "travail",
  "revision": "<head_complet du terrain gelé>",
  "fichiers": [{ "chemin": "AGENT.md", "sha256": "…", "taille": 1234 }]
}
```

et ses lignes entrent dans l'empreinte sous la forme `installation\t<chemin>\t<sha256>`, plus une ligne de
révision. La règle est conditionnelle : un gel sans `installation` garde son empreinte à l'octet près, donc
les seize gels existants restent valides ; un gel qui porte le champ ne peut plus ni le perdre ni le modifier
sans que `verifierLeGel` refuse, puisque l'empreinte recalculée changerait.

Au gel, trois refus :

1. un chemin déclaré n'existe pas dans le terrain, ou n'est pas un fichier : nommé, avec la déclaration ;
2. un chemin est absolu, ou sort de l'arbre ;
3. la déclaration est illisible, `fichiers` est vide, ou `geste.preuve` manque.

Sans déclaration, rien ne change : ni le gel, ni son empreinte, ni la porte.

## 3. La règle dans la porte

`preflight`, après `verifierLeGel` et après la vérification de l'arbre de travail (`memeArbre`), relit
`installation.fichiers` dans le dossier où la session va s'ouvrir, et refuse :

1. un fichier déclaré absent : « l'installation déclarée n'est plus dans l'espace de travail » ;
2. un fichier dont le `sha256` diffère du gelé : les deux empreintes courtes, le chemin, et le fait que la
   session lirait un AIDD qui n'est pas celui du gel ;
3. une incohérence entre les deux pièces : une entrée `fichiers` de rôle `installation` sans champ
   `installation`, ou l'inverse.

La porte écrit dans `gate.json` ce qu'elle a mesuré : la révision, l'empreinte de l'installation et le compte
des fichiers, à côté du gel et de l'arbre (`run.mjs:995`). Le reçu lit la porte ; rien de neuf n'y est ajouté.

## 4. Ce qu'elle refuse, en une liste

- **au gel** : déclaration illisible, `fichiers` vide, `geste.preuve` absent ; chemin absolu ou hors de
  l'arbre ; fichier déclaré absent du terrain.
- **à la porte** : fichier de l'installation absent ; `sha256` reçu différent du gelé ; rôle `installation`
  dans le gel sans champ `installation`, ou champ sans le rôle ; empreinte du gel recalculée différente de
  l'écrite, ce que la règle du §2 provoque dès qu'une ligne d'installation bouge.

## 5. Ce qu'elle n'atteste pas

- Le geste humain : `geste` est déclaré, personne ne l'a vu.
- Que l'installation soit celle de l'installeur officiel d'AIDD : le cas choisit les fichiers qu'il tient
  pour la trace de l'installation. Une installation faite à la main passe si ses traces sont celles
  déclarées.
- Que l'AIDD installé fonctionne : un fichier présent et stable n'est pas un skill qui marche.
- Que la session s'en soit servie : c'est la trace du run qui le dira, pas la porte.

## 6. Les cinq contrôles

- `351` : un cas qui déclare son installation gèle (`0`) et la porte l'accepte (`0`), sur une copie des cas
  et un terrain de banc.
- `352` : au gel, un fichier déclaré absent du terrain fait refuser en `1`, en le nommant.
- `353` : après le gel, le fichier du terrain est modifié ; la porte refuse en `1` en nommant le chemin et
  les deux empreintes.
- `354` : le champ `installation` du gel est réécrit, un `sha256` changé ; `preflight` refuse en `1` sur
  « le gel ne concorde pas avec lui-même ».
- `355` : un gel existant sans le champ (`plan-simple`) passe `preflight` avec la même empreinte :
  non-régression.

Le banc passe de 350 à 355 contrôles.

## 7. Ce que ça coûte

- `run.mjs` : `empreinteDeGel` (lignes conditionnelles), `freeze` (lecture et mesure de la déclaration,
  trois refus), `preflight` (relecture et trois refus), `gate.json` (un champ) ;
- `banc-harnais.sh` : cinq contrôles ;
- `PROTOCOLE.md` : le geste d'installation et la ligne de `preflight` ; `ARCHITECTURE.md` : la ligne de
  `preflight` et le champ du gel ; `BANC.md` : le groupe et le total ;
- une ADR à l'approbation, parce que le champ change ce qu'un gel atteste.

## 8. Ce qui pourrait l'invalider

Si le framework expose un installeur stable et versionné, cette spec devient inutile : mieux vaudrait
mesurer l'installeur que vérifier une déclaration. Si le terrain doit rester un clone pur, l'installation
appartient au cas et non au projet, et le champ mesure alors la préparation du banc, pas un geste de la
personne.
