# Spec — consolider le protocole de test

> V0.1, 2026-10-23. Source : [brainstorm du même jour](../../../brainstorm/2026-10-23-030728-consolider-le-protocole.md)
> §3, [ADR-069](../../../DECISIONS.md) (la pause est un tour `user`), [ADR-074](../../../DECISIONS.md)
> (le test se joue dans la conversation courante) et la spec du run guidé du 22:12, qui laisse l'export
> du fil **optionnel**. Rien n'est appliqué avant approbation.

## 1. Le défaut, mesuré

- **Le mode par défaut n'a pas de trace.** Le run guidé du 21:37 est un recast du rapport ; son fil n'est
  pas exporté, et la Séance 124 n'a pu tenir que le chemin, la forme et l'empreinte du produit. La grille
  du gabarit cite des tours que rien ne vérifie.
- **`ouvrir` compte une session arrêtée comme un run fini.** Sur le run `211526`, le brouillon finissait
  par « : » : `questionEnTexte` rend `null`, la boucle sort, `ouvrir` imprime un succès à **0** question,
  et la réponse figée part à la main. Sur le run `182505`, le refus de délai ne nomme pas le fil : la
  reprise n'a pas d'identifiant.
- **La pause n'a pas de durée.** `receipt.pause` porte cinq clés et la limite dit « sa durée n'est pas
  mesurée » ; un tour dans la même seconde que le message précédent compte comme une attente.

## 2. R2 — `ouvrir` refuse une session arrêtée sans question

Dans la boucle de `commandeOuvrir`, quand la session est inactive, qu'aucun formulaire n'attend et que
la dernière part `text` d'un message `assistant` postérieur à la référence **ne finit pas** par `?` :

- si aucune réponse figée ne reste à jouer → `break`, comme aujourd'hui : le run est fini ;
- si une réponse reste à jouer → **refus** (`exit 1`), sans envoyer de message :

```text
REFUS — la session <fil> s'est arrêtée sans question après <n> réponse(s) jouée(s) : dernière ligne
« <80 caractères> » — réponds à la main, puis « suite --fil <fil> » ; le run n'est pas un succès à zéro
question
```

La ligne citée est la dernière ligne non vide hors bloc de code, celle que `derniereLigneHorsBloc` rend
déjà. Le refus de délai gagne le fil :

```text
REFUS — la session <fil> n'est pas devenue inactive en <N> min — elle est peut-être encore vivante, et
rien ne se conclut d'un tour inachevé ; le fil reste lisible par « suite --fil <fil> »
```

Rien d'autre ne change : formulaire, question terminée par `?`, ordre des réponses, code `0` d'un run qui
finit sans question quand toutes les réponses sont jouées.

## 3. R3 — `pause.attente_ms`

`receipt.pause` gagne une clé, `attente_ms` : l'entier de millisecondes entre l'instant de la part qui
précède immédiatement le tour `user` de la pause (par `index`) et celui de ce tour, ou `null` si l'un des
deux instants n'est pas un nombre fini. Aucun autre champ ne bouge.

La limite qui disait « sa durée n'est pas mesurée » devient :

```text
la pause est mesurée comme un tour `user` entre l'ouverture et la première écriture nommée : sa durée est
l'intervalle entre la part précédente et ce tour, jamais une attente humaine (ADR-069, ADR-078)
```

Quand `attente_ms` est un entier inférieur à `1000`, une limite de plus :

```text
la pause a été donnée <n> ms après la part précédente : elle prouve un tour, pas une attente humaine
```

Un reçu antérieur, sans `attente_ms`, reste lisible et n'est jamais réécrit : le champ absent se lit
comme `null`, comme `conduite` avant l'ADR-071. Le calcul ne touche ni `pause.mesuree`, ni
`question_sans_reponse`, ni le verdict.

## 4. R1 — `tracer`, la trace du run guidé

### 4.1 Usage

```text
node docs/device/harness/orchestrer.mjs tracer --run <dossier> --fil <id> [--client auto|freebuff|opencode] [--store <dir>]
node docs/device/harness/orchestrer.mjs tracer --run <dossier> --liste --depuis <iso>
```

`--run` désigne le dossier d'un run guidé : il contient **exactement un** fichier dont le nom finit par
`-run-guide.md`. Un autre dossier est refusé, avant tout appel au client.

### 4.2 `--fil`

Le client se choisit comme pour `suite` : `--client` s'il est donné, sinon les deux sont détectés ; zéro
candidat est un refus qui nomme les deux sources, deux candidats un refus qui nomme `--client`. La trace
s'exporte par `exportTrace`, la session se lit par `session` (même frontière, `clients.mjs`), et deux
pièces sont écrites, rien d'autre :

- `trace/echange.jsonl` : l'export normalisé, tel que `suite` l'écrit pour un run indépendant ;
- `trace/fil.json` :

```json
{
  "type": "fil",
  "client": "freebuff",
  "application": "Freebuff Desktop (desktop-v2.db)",
  "identifiant": "…",
  "modele": "…",
  "dossier": "/chemin/absolu/du/run",
  "exporte_le": "2026-10-23T03:00:00+02:00",
  "messages": 128,
  "premier": { "seq": 1, "ts": "2026-10-22T21:13:56+02:00" },
  "dernier": { "seq": 128, "ts": "2026-10-22T21:37:12+02:00" },
  "trace": {
    "chemin": "/chemin/absolu/du/run/trace/echange.jsonl",
    "sha256": "…",
    "lignes": 128,
    "source": "…",
    "commande": "…"
  }
}
```

`messages` est le nombre de lignes écrites ; `premier` et `dernier` sont le `seq` et le `ts` de la première
et de la dernière ligne. Le `sha256` se calcule sur les octets écrits, pas sur une relecture.

Refus, tous en `1` et sans écrire : fil inconnu, client ambigu, fil en worktree ou hors d'un répertoire
résolvable (les refus de `session`), `trace/echange.jsonl` déjà présent, dossier sans run-guide unique.

### 4.3 `--liste --depuis <iso>`

Rend, pour chaque base Freebuff, les fils dont `created_at` est postérieur à `--depuis`, du plus récent
au plus ancien : `id`, modèle, nombre de messages, début. Aucun contenu de message n'est imprimé.
`--depuis` est obligatoire : une liste non bornée ne se lit pas. `--liste` n'écrit rien et ne demande pas
`--fil`.

### 4.4 Le gabarit du run guidé

La spec du 22:12 reste la forme du document ; cette spec l'amende par un **§5 bis** à ajouter au fichier
`*-run-guide.md` quand `tracer` a rendu une trace :

```markdown
## 5 bis. Trace machine

- fichier : `<chemin>/trace/echange.jsonl` ;
- `sha256` : `<empreinte>` ;
- lignes : `<n>` ;
- fenêtre : `<depuis> → <jusqu>`, `seq` `<premier>` à `<dernier>` ; un export sans borne le dit, il ne laisse pas croire à un run ;
- source : `<client, modèle, fil>`.

La fenêtre se choisit avant l'export et ne se réécrit pas après : une preuve hors fenêtre n'est pas un geste
absent, elle est hors mesure (spec du 2026-10-23 14:43).

Les preuves du §4 citent un `seq` de ce fichier. Une ligne que la trace ne porte pas reste `non observé`.
```

Sans trace, le §5 bis dit `absente` et nomme la raison ; aucune ligne du §4 ne devient `tenu` sur un tour
que rien ne peut lire.

## 8. ADR réservées

- **ADR-076** — le run guidé attache sa trace machine, et le gabarit cite des `seq`.
- **ADR-077** — une session inactive sur un texte sans `?` n'est pas un run fini ; le fil se nomme.
- **ADR-078** — la pause porte son intervalle, jamais une attente humaine.

## 9. Ce que cette spec ne fait pas

- Elle ne rend pas le run guidé indépendant, et ne change pas l'ADR-074.
- Elle n'écrit aucun reçu pour un run guidé : `tracer` ajoute une source, pas une attestation.
- Elle ne confronte pas la phrase du juge au nombre de fichiers : la mesure manque (brainstorm §4).
- Elle ne rouvre pas le headless, et n'ajoute aucun cinquième verdict.
- Elle ne réécrit aucun reçu antérieur.

## 10. Ce qui la rendrait fausse

Une grille `tenu` citant un `seq` absent de la trace jointe. Un `tracer` qui écrit hors de `trace/`, ou
dans un dossier sans run-guide. Un `ouvrir` qui rend un succès à zéro question sur un texte sans `?`. Un
refus de délai sans le fil. Un `attente_ms` qui n'est pas l'écart des deux instants, ou une pause courte
sans sa limite. Un reçu antérieur refusé faute du champ.
