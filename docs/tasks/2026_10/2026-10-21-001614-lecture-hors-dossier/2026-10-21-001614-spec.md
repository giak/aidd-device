# Spec — une lecture hors du dossier du cas interdit le verdict conforme

> V0.1 — 2026-10-21, née à **00:16:39** (`stat -c %w`) ; le nom porte `001614`, écart de **25 s**
> nommé. Suite directe du [rapport utilisateur du second run du cas jouet](../../../device/runs/2026-10-20-222845-50664060-3d0db46/RAPPORT.md).

## 1. Le défaut

Le run `2026-10-20-222845-50664060-3d0db46` est `conforme`, alors que sa trace montre deux lectures
hors du dossier du cas : `aidd-device-work/README.md` et le
`kit-ouverture.md` du cas `2026-10-15-133423-promesse-memoire-avant-ecriture`, aux lignes 16 et 17,
puis deux `grep` dans le `framework-origin` de ce même cas, aux `seq` 11 et 12. Le reçu ne mesure que
`cloisonnement.attendu_vu` ; il ne regarde aucun chemin lu. Un run peut donc lire le kit d'un autre cas
et rester `conforme`.

## 2. La règle

`receipt` lit les parts `tool` de la trace normalisée dont le nom d'outil appartient à la famille de
lecture `read|grep|glob|search|find|cat|view` et dont `chemin_outil` est une chaîne. Pour chacune :

- un chemin absolu est résolu tel quel ; un chemin relatif est résolu depuis le répertoire de travail
  du run ;
- les liens sont résolus quand la cible existe, sinon le chemin absolu est comparé lexicalement ;
- le chemin doit être **dans le dossier du cas**, c'est-à-dire sous
  `<gel.racine_espace_de_travail>/<cas>`. Ce dossier contient `terrain/`, `framework-origin/` et
  `origine/` ; il ne contient ni le kit d'un autre cas, ni le README de la racine des espaces de
  travail, ni `docs/device/CASES/`.

Toute lecture hors de ce dossier devient `falsificateurs.lecture_hors_dossier`, une liste d'objets
`{ seq, index, ts, outil, chemin }`. Le reçu pousse alors un motif
« une lecture est sortie du dossier du cas : seq …, outil …, chemin … (demande §7) » et **refuse tout
verdict autre que `non concluant`**, comme les autres falsificateurs. Le run peut encore produire un
reçu `non concluant`, qui nomme la lecture ; il ne peut plus produire un `conforme`.

Un chemin lu qui ne résout pas est traité comme un chemin lexical : une lecture tentée hors du dossier
reste une lecture hors du dossier. Un chemin relatif est celui de la session, pas celui du harnais.

## 3. Ce que la règle ne mesure pas

- Les outils `shell`, `bash` ou `terminal` : la trace normalisée ne porte pas leur commande, donc un
  `cat` ou un `grep` lancé par ce canal reste invisible. Le reçu ajoute une limite nommée quand la trace
  contient un outil de cette famille sans chemin.
- Les outils sans nom ou sans `chemin_outil` : ils ne se classent pas ; le reçu le dit déjà pour les
  outils d'écriture, et la même limite vaut pour la lecture.
- Ce que le contenu lu change dans la décision de la session : la règle constate le chemin, pas
  l'influence.
