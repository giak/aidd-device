```text
python3 - <<'PY'

f="/home/giak/projects/aidd-device/docs/device/CASES/2026-10-15-133423-promesse-memoire-avant-ecriture.freeze.json"
g=json.load(open(f)); sha=lambda p: hashlib.sha256(open(p,'rb').read()).hexdigest(); l=[]
for x in g["fichiers"]:
    h=sha(x["chemin"]); l.append(f'{x["role"]}\t{os.path.basename(x["chemin"])}\t{h}'); print("fichier", x["role"], h==x["sha256"])
for r in g["references"]:
    p=os.path.join(r["racine"],r["chemin"]); h=sha(p); l.append(f'reference\t{r["chemin"]}\t{h}'); print("reference", r["chemin"], h==r["sha256"])
print("empreinte", hashlib.sha256(("\n".join(sorted(l))+"\n").encode()).hexdigest()==g["empreinte"])
PY
→ 10 fois True, puis empreinte True
```

Un seul `False` sur un fichier du cas ou une référence rend le gel caduc : **ne pas ouvrir la
session avant de refaire le gel** (sa commande complète est dans le champ `commande` du
`.freeze.json` ; `--refreeze` détruit le précédent, et c'est la nouvelle empreinte que le reçu
portera).

## 3. Ce qui doit revenir

### 3.1 L'ordre, et les commandes

```text
H=/home/giak/projects/aidd-device/docs/device/harness/run.mjs

node "$H" collect --run "$RUN" --case "$CAS" --from "$W/terrain/aidd_docs"
# à la main, ensuite : raw/$CAS/last-message.md (le dernier message de la session, tel quel)
# et trace/ (l'export et la commande qui l'a produit)
node "$H" receipt --run "$RUN" --case "$CAS" --faits faits.json
# le juge, ensuite, sur le reçu SEUL :
node "$H" compare --run "$RUN" --case "$CAS" \
  --difference "<ce que le produit fait>" \
  --phrase "<au vu de l'attendu écrit, le produit fait X ; l'attendu disait Y>" \
  --verdict conforme|ecart|non concluant --limites mord|ne mord pas|non évaluable
```

1. **`collect`** copie verbatim le produit sous `raw/<cas>/` et écrit son manifeste : `sha256`,
   taille, `birth` de chaque fichier, et la source absolue. Le produit attendu est la table
   `Write to` de `references/memory-destinations.md`, donc `terrain/aidd_docs/` — tout le reste est
   hors produit (demande §6), même écrit dans le répertoire de travail.
   Il refuse : un dossier déjà collecté (deux collectes font deux produits), un lien symbolique
   (une sortie du répertoire de travail n'est pas un produit), une copie dont le `sha256` diffère,
   un `--from` vide.
2. **`last-message.md`** s'écrit après lui, à la main : le dernier message de la session, verbatim.
3. **`trace/`** reçoit l'export du §1.5 et sa commande.
4. **`receipt`** s'écrit à chaud, pendant le run, et refuse d'écraser un reçu existant : un reçu
   reconstruit le lendemain est un témoignage, pas un reçu. Il exige le gel, le manifeste et
   `faits.json` ; il remesure les quatre arbres ; il vérifie les quatre falsificateurs du §5.
5. **`compare`** appartient au juge, pas au run : il travaille sur le reçu seul, ne voit pas la
   session, et écrit `output.json` — l'attendu, le produit brut, la différence, la phrase de
   verdict, les limites, et les attendus écartés comme non testables.

### 3.2 Les quatre falsificateurs, et ce que le harnais ne lit pas

Un seul suffit à faire tomber le run, et le verdict suit la preuve (spec §7) :

| Condition (§5) | Ce qui la fait mordre |
| --- | --- |
| 1 — naissance | le `birth` d'un fichier produit est antérieur au gel |
| 2 — trace | la trace machine ne porte aucun échange dans la fenêtre du run |
| 3 — arbre | le produit existe alors que le `porcelain` de `travail` est inchangé |
| 4 — empreinte | le produit est identique à un fichier déjà présent avant le run |

La condition 2, le harnais **ne peut pas** la lire : il l'écrit lui-même en limite (« le harnais ne
lit aucune des trois sources du §5.1 »). La pièce (1) est attestée par l'export, pas par ce script.

### 3.3 Le plafond du verdict

- naissance **et** trace **et** arbre → le cas peut être `conforme` ou `écart` ;
- trace et arbre, sans la naissance → verdict possible, la limite dite dans le reçu ;
- sans naissance ni trace → `non concluant`, quoi que dise l'opérateur ;
- cloisonnement rompu → `non concluant`, dans tous les cas.

Le reçu porte ces limites, et la phrase de verdict — « au vu de l'attendu écrit, le produit fait X ;
l'attendu disait Y » — n'attribue ni faute ni mérite : elle compare.

- **Les interdits du §7 de la demande — arbitrés le 2026-10-15 (ADR-015), plus `OPEN`.** Le §5 garde
  sa lettre : le texte remis est ces deux lignes et rien d'autre. Les interdits ne sont donc pas dits ;
  ils doivent être **structurellement** vrais à l'ouverture, et c'est ce qui a été mesuré. À la
  révision sous test, aucune étape de la skill n'écrit hors du projet : `references/tools.md` et
  `hooks/update_memory.js` visent `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md` et

  l'appelle (le `git add` n'appartient qu'au hook automatique). Ce qui a réellement fait sortir un
  agent du cadre, deux fois le 2026-10-15, n'est pas un manque de paroles mais la résolution d'un
  chemin relatif par le client contre **sa** racine de projet ; aucun interdit énoncé ne l'aurait

- **Le verdict** : personne ne le connaît avant le run, et cette page ne l'anticipe pas.
